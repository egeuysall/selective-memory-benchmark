## The result to carry forward

Use the manually audited score as the manuscript headline. Keep the automated
keyword score beside it so readers can see how much the rubric affected the
result.

| Approach | Automated label | Audited correct | Audited accuracy | Estimated total token proxy | Observed wall time |
|---|---:|---:|---:|---:|---:|
| Large context | 23/30 | 27/30 | 90.0% | 9,085 | 150.057 s |
| Traditional TF-IDF RAG | 21/30 | 24/30 | 80.0% | 15,236 | 108.809 s |
| Selective memory | 25/30 | 29/30 | 96.7% | 12,484 | 217.326 s |

RAG retrieved at least one supporting current event for 28/30 questions, all
supporting events for 23/30, a partial set for 5/30, and none for 2/30.
Selective memory was the only highest-scoring approach on Q16, Q17, and Q25.
Its remaining miss was Q23, an event-provenance error: it cited nearby
keyboard-coverage events instead of the requested E081 and E086.

The cost column is an estimated token proxy using `ceil(characters / 4)`, not
billable USD. Exact dollar cost cannot be claimed from this replay because the
runner did not expose a model price schedule or invoice-level token usage.
Compared with traditional RAG, selective memory used 18.1% fewer estimated
total tokens but took 99.7% longer in this one replay. RAG was fastest. Do not
turn these three metrics into a composite winner score.

## How to start writing

Start with Methods, not the abstract. Copy this working scaffold into a new
Week 8 document and replace the bracketed text:

### 1. Working title

**Selective Memory for Temporal Project-State Recall: A Three-Way Benchmark
Against Large-Context Prompting and TF-IDF Retrieval**

### 2. Opening claim

> We evaluated three ways of supplying project history to an AI system: full
> context, traditional retrieval, and selective memory, using the same 30
> questions over a fictional 90-event software project timeline.

### 3. Methods paragraph order

Write one paragraph for each item:

1. Dataset: fictional ShieldPath Learning Lab timeline, 90 events, 30 days,
   current state plus historical conflicts.
2. Questions: 30 questions covering owners, blockers, requirements, deadlines,
   canceled work, outdated facts, and event-level transitions.
3. Conditions: all events; top-five TF-IDF cosine retrieval; generated memory
   table with current/updated/outdated/canceled facts and `Use`/`Ignore`.
4. Evaluation: same model and question set, saved JSON answers, transparent
   automated rubric, and manual review of every non-Correct automated row.
5. Efficiency: estimated token proxy and one observed wall-time replay; explain
   why neither is an exact USD or latency estimate.

### 4. Results paragraph order

Begin with the audited table: selective memory 29/30, large context 27/30,
and RAG 24/30. Then state the automated scores in a separate sentence. Next
describe the RAG coverage result. Finish with the metric-specific tradeoff:
selective memory was most accurate and lower-token than RAG, but RAG was faster.

Keep this section observational. Do not explain why an approach worked until
the Discussion section.

### 5. Discussion paragraph order

- **Where selective memory helped:** repeated-owner reasoning (Q16), the
  resolved-to-later-blocker transition (Q17), and canceled-feature filtering
  (Q25).
- **Why the result is balanced:** selective memory did not win every question;
  Q23 shows that a compact memory can preserve nearby facts while still
  missing the exact event provenance requested.
- **Engineering tradeoff:** lower prompt-token proxy and higher audited
  accuracy came with slower observed end-to-end time in this replay.
- **Interpretation boundary:** these findings are limited to this synthetic
  dataset, model run, prompt design, and scoring protocol.

### 6. Limitations and future directions

Use concrete limitations: one live replay, 30 questions, synthetic data,
keyword-rubric subjectivity, one initial manual reviewer, TF-IDF lexical
matching, and unavailable billable USD. Then propose repeated trials,
independent reviewers, larger datasets, semantic retrieval, and measured token
billing as future work.

### 7. Abstract last

After Methods, Results, Discussion, and Limitations are stable, write four
sentences: problem, method, main audited result, and limitation. This prevents
the abstract from claiming more than the evidence supports.
